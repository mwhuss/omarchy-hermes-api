# Multiplexed Endpoint and Profile Routing Architecture

To support diverse Hermes setups ranging from multi-gateway deployments to single servers multiplexing multiple personas under one host, requests are resolved and scoped by `(endpointId, profileName)` Agent Targets. In compliance with the official Hermes gateway multi-profile specification (`gateway.multiplex_profiles`), requests directed to named profiles route through the `/p/<profile>/` path prefix (covering both OpenAI-compatible endpoints `/p/<profile>/v1/...` and Hermes session management `/p/<profile>/api/sessions/*`) with per-profile bearer authentication, while the inherent default profile retains standard un-prefixed routes. Client-side session state, in-flight streaming processes, and local caches are partitioned by `${endpointId}:${profileName}:${sessionId}` to eliminate cross-talk across disparate agents, and active target filtering defaults to a unified "Hermes" view supporting seamless multi-agent concurrency.
